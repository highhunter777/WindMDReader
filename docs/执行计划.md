## 四、执行顺序与理由(历史记录,已于 2026-10-08 执行完毕)

```
T0.1 修复 Rust 工具链
  └─> T0.2 Tauri 脚手架        ← 先做,后续能力全部依赖它
        ├─> T2.x M2 知识库能力
        └─> T3.x 导出等

T1.1 查找断链      ← 与 T0 并行,不依赖 Rust
T1.3 CommonMark    ← 与 T0 并行,不依赖 Rust
T1.2 图片灯箱      ← 纯前端,并行
```

**为什么 Rust 后端必须先行**:文件树、双链、反链、标签、文件监视全都依赖真实的库目录抽象。mock 层每次都要手写假数据,M2 开始会反复返工;且 Tauri 脚手架越晚搭,`ipc/tauri.ts` 的 11 处 `invoke` 与实际 command 签名对不上的风险越高。

**为什么 T1 三项不阻塞 T0**:纯前端工作,与 Rust 无依赖,可并行。
