# WindMD — 高级 Markdown 阅读器 项目规划文档

> 版本:v0.1(草案) · 日期:2026-10-07 · 状态:待评审
> 本文档定义产品定位、功能范围、技术选型、架构设计与实施里程碑,供立项与开发参考。

## 1. 项目概述

### 1.1 一句话定义

WindMD 是一款**本地优先、高性能、可定制**的 Markdown 阅读器,面向开发者与知识管理者,提供接近 IDE 级的大文件性能与接近出版级的阅读体验。

### 1.2 定位与差异化

| 产品 | 定位 | 与 WindMD 的差异 |
|---|---|---|
| Typora | 编辑器,所见即所得 | WindMD 强调**阅读**体验与浏览效率,编辑为次要能力 |
| Obsidian | 知识库,双链生态 | WindMD 更轻量、打开更快、阅读性能更强,插件非核心 |
| VS Code 预览 | 编辑器附带的视图 | WindMD 是独立阅读器,提供更完整的阅读模式(专注/主题/导出) |
| MarkText / Zettlr | 开源编辑器 | WindMD 以模块化流水线、性能优先为卖点 |

**核心卖点(优先级排序):**

1. **快** — 10MB / 万行级文档秒开,滚动 60fps
2. **好看** — 精心调校的排版、主题系统、代码/数学/图表渲染
3. **好用** — 目录导航、全文搜索、阅读进度、双链与反链
4. **本地优先** — 数据不出本机,无遥测,文件格式即 `.md`,无锁定

### 1.3 目标用户与场景

- **开发者**:阅读 README、技术笔记、API 文档、CHANGELOG
- **知识管理者**:Obsidian/Logseq 库的重度阅读者,想要更快的查看器
- **写作者**:写作完成后的校对排版、导出发布
- **学生/研究人员**:论文笔记、含公式与图表的教材

典型场景:
- 打开一个含 2000 行、50 张图、10 个 mermaid 图表的「大型项目笔记」,1 秒内可读
- 长文阅读时,侧边目录随滚动高亮,右上角显示阅读进度
- 在笔记库中全文搜索「认证」,1 秒内返回带上下文的结果

## 2. 功能规划

功能按优先级分级:**P0(必须,首版交付) / P1(重要,第二版) / P2(增强,后续)**。

### 2.1 核心阅读能力(P0)

#### 2.1.1 Markdown 渲染
- [ ] 完整 **CommonMark 规范**兼容(通过官方 spec 测试集 652 例)
- [ ] **GFM 扩展**:表格、任务列表(`- [ ]`)、删除线、自动链接、围栏代码块
- [ ] 脚注(`[^1]`)、定义列表、上下标(`~sub~ ^sup^`)等扩展语法
- [ ] **数学公式**:KaTeX,行内 `$...$` 与块级 `$$...$$`
- [ ] **Mermaid 图表**:流程图、时序图、甘特图、状态图,按需懒加载
- [ ] **代码高亮**:Shiki(TextMate 语法,VS Code 级观感),带行号、复制按钮
- [ ] 标题锚点;点击目录/标题平滑滚动
- [ ] **Emoji/图标**:`:smile:` 短码与 GIF 动图支持

#### 2.1.2 图片处理
- 相对路径、绝对路径、`file://`、网络 URL 图片
- 图片懒加载 + 占位(保持布局稳定,防滚动跳动)
- 点击图片 → 灯箱大图预览,支持缩放、旋转、左右切换
- 图片加载失败展示出错占位与原因

#### 2.1.3 阅读导航
- **目录(TOC)侧边栏**:从标题自动生成,滚动时高亮当前节
- 文档内查找/高亮,支持正则
- **阅读进度记忆**:记录滚动位置与小节,重开文档恢复到原处
- 翻页/滚动的快捷键导航(`g` 跳转,`j/k` 行移动,`[ ]` 前后标题)
- 双栏**滚动同步**(左右分屏查看同一文档两个位置)

#### 2.1.4 双链与知识库(类 Obsidian)
- [ ] `[[Wiki 链接]]` 解析与点击跳转,支持 `[[链接|显示名]]`
- [ ] 未建立链接的灰色提示(点击可创建目标文件)
- [ ] **反向链接面板**:当前文档被谁引用
- [ ] 标签解析(`#tag`),标签聚合视图

#### 2.1.5 文档管理
- **库(Vault)概念**:选择一个目录作为知识库根
- 文件树侧栏:目录展开/折叠、新建/重命名/删除(走系统回收站)
- 最近打开、收藏/星标、标签管理
- **全文搜索**:索引化,毫秒级返回,结果带上下文片段与关键词高亮
- 外部文件变更自动重载(文件监视)

### 2.2 阅读体验增强(P1)

#### 2.2.1 阅读模式
- **专注模式(Zen)**:隐藏全部 UI 只留正文,`Esc` 退出
- **打字机/焦点行模式**:当前段落居中并提亮,其余内容减弱(适合长文)
- 排版实时调节:字号、行距、栏宽(阅读宽度)、字体(正文/代码)、左右边距
- 浅色 / 深色 / 跟随系统三态主题,支持自定义 CSS
- 高对比度 / 护眼(纸色)模式

#### 2.2.2 辅助能力
- **朗读(TTS)**:选段/全文朗读,可调语速,支持中英文音色
- **划词翻译**:选中文本弹出翻译(离线词典优先,在线 API 可选)
- 多语言界面(中/英),i18n 框架预留

#### 2.2.3 导出与分享
- 导出 **PDF**(打印流排版,保留代码高亮与公式)
- 导出 **HTML**(单文件,内嵌图片/样式,可直接分享)
- 导出**长图**(整页截图,适合发博客/社交平台)
- 复制为 HTML/纯文本;导出为 Word(可选,pandoc 集成)

### 2.3 编辑能力(P2,可选范围)

> 若定位为「阅读器」,编辑仅需提供轻量内联编辑;完整编辑器特性可在 2.x 版本引入。

- 内联编辑:双击进入编辑,`Ctrl+E` 切换编辑/预览
- 快捷键:加粗/斜体/标题/链接/列表,Markdown 源码级
- 自动保存 + 版本快照(可选)
- 拖拽图片入文自动落盘并生成相对路径引用

### 2.4 明确不做(第一版)

- ❌ 云同步(只做本地文件)
- ❌ 完整插件市场(预留接口,不发布生态)
- ❌ 多人协作 / 实时共享
- ❌ WYSIWYG 双栏实时同步编辑(复杂度高,收益低于阅读优先定位)

## 3. 非功能需求(NFR)

### 3.1 性能目标

| 场景 | 目标 | 验证方式 |
|---|---|---|
| 打开 10MB / ~1 万行 Markdown | ≤ 1s 可交互 | 基准文档 + performance 面板 |
| 打开 2000 行常见笔记 | ≤ 300ms | 同上 |
| 长文档滚动 | 稳定 60fps | DevTools FPS 录制 |
| 全文搜索(1 万文件库) | ≤ 200ms 返回 | 实测 |
| 冷启动 | ≤ 1.5s(桌面端) | 启动计时 |
| 内存占用(日常 10 文档打开) | ≤ 300MB | 任务管理器 |

### 3.2 兼容性
- 平台:Windows 10+ / macOS 12+ / Linux(桌面版);Web 版仅作为阅读器(optional)
- 分公司:CFR 可空。跨平台 WebView:Windows 用 WebView2、macOS 用 WKWebView、Linux 用 WebKitGTK,须在前端避免平台差异 API,统一用特性检测

### 3.3 隐私与安全
- 全部数据本地;无遥测、无账号、无网络请求(除非用户显式启用在线翻译/更新)
- 渲染的 HTML 一律经 sanitize(DOMPurify),防止 `.md` 内嵌脚本(XSS)
- 插件若引入,须沙箱 + 权限声明

### 3.4 可访问性
- 键盘全流程可操作;ARIA 标注;`prefers-reduced-motion` 支持
- 对比度满足 WCAG AA

## 4. 技术选型

### 4.1 客户端形态决策

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **Tauri 2**(Rust + WebView) | 体积 ~10MB、内存低、性能好、Rust 后端适合索引/搜索 | WebView 三平台差异需处理;生态较 Electron 年轻 | ✅ **推荐** |
| Electron | 生态最成熟、Chromium 一致性强 | 体积 ~100MB+、内存高 | 备选(若团队重前端) |
| 纯 Web(PWA) | 零安装、易分发 | 无法深度访问文件系统;性能受限 | 可作轻量阅读版 |

**推荐:Tauri 2 + React + TypeScript**。
理由:阅读器是 I/O + 渲染密集型,Tauri 的 Rust 层做文件监视、全文索引、搜索非常契合;WebView2 在 Win11 系统自带,安装包可压缩到个位数 MB。

### 4.2 渲染引擎选型(关键决策)

| 引擎 | 特性 | 性能 | 插件生态 | 结论 |
|---|---|---|---|---|
| **markdown-it** | 同步渲染、规则可覆写、速度快 | ★★★★★ | markdown-it-* 丰富 | ✅ **主引擎** |
| remark/unified | AST 驱动、可编程性强、生态大 | ★★★☆(AST 开销) | remark-*/rehype-* | 用于需要 AST 的插件(双链/自定义) |
| marked | 最轻最快之一 | ★★★★★ | 较少 | 备选 |

**推荐:markdown-it 为渲染主引擎**,理由:
1. 阅读器是「渲染一次展示」场景,markdown-it 同步生成 HTML,无 AST 中间态,性能约比 remark 快 2~4 倍;
2. 支持覆写/扩展单个 token 渲染规则,便于给代码块、表格、任务列表注入自定义逻辑;
3. 配合 `markdown-it-footnote`、`markdown-it-container`、`markdown-it-task-lists` 等社区插件即覆盖 80% 语法。

若将来需要「编辑器 ↔ 预览」双向同步或复杂 AST 转换,再引入 unified 做第二通道,两者不冲突。

### 4.3 周边库选型

| 领域 | 首选 | 备选 | 说明 |
|---|---|---|---|
| 代码高亮 | **Shiki** | highlight.js / Prism | Shiki 用 TextMate 语法,观感与 VS Code 完全一致;代价是慢 → 用「视口内才高亮」+ 结果缓存 |
| 数学公式 | **KaTeX** | MathJax | KaTeX 快 ~5 倍、输出可读;MathJax 兜底复杂公式 |
| 图表 | **Mermaid**(懒加载) | Kroki(在线服务,不推荐) | Mermaid 渲染重,只对进入视口的图表实例化 |
| HTML 清洗 | **DOMPurify** | — | 安全底线,不可省 |
| 状态管理 | **Zustand** | Redux Toolkit | 轻量、无样板、适合中等复杂度 |
| 全文搜索 | **SQLite FTS5**(前端) + **Tantivy**(Rust 可选) | — | 见 4.4 |
| 图标/动效 | @phosphor-icons / Framer Motion | — | — |

### 4.4 全文搜索方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| SQLite FTS5 | 集成简单、事务一致、Millions 行无压力 | 中文分词需自定义 tokenizer(可用 trigram 或按字符) |
| Tantivy(Rust) | 极快、原生中文分词(jieba) | 需要独立索引文件与同步逻辑 |
| 自己写倒排表 | 可控 | 工程量与维护成本高 |

**推荐:SQLite FTS5 + 自定义中文分词**(首选,简单可靠);若实测中文检索质量不足,升级为 Tantivy 作为后端,前端接口不变(搜索模块抽象)。

### 4.5 前端工程栈

- 构建:Vite 5 + TypeScript strict
- UI:自研组件(阅读器个性化强,不引重型 UI 框架);工具函数用 Radix primitives(无头组件)
- CSS:原生 CSS 变量 + 设计 token(主题核心),不用 Tailwind(排版样式需精细控制)
- 测试:Vitest(单测)+ Playwright(端到端,含 CommonMark spec 用例回归)

### 4.6 Rust 后端职责

- 文件系统:读取(list/read/watch)、原子写入、回收站删除
- 文件监视:`notify` crate → 事件节流 → 增量刷新
- 索引:文档元数据 + FTS 索引的后台构建与更新
- 搜索:跨库查询、片段生成
- 可选:pandoc 导出、TTS 调用

## 5. 架构设计

### 5.1 总体架构

```
┌────────────────────────────────────────────────────┐
│                    前端(WebView)                    │
│ ┌────────────┐ ┌──────────────────────────────┐    │
│ │  UI 层      │ │  渲染管线                     │    │
│ │  侧栏/内容/ │ │  markdown-it → HTML           │    │
│ │  大纲/设置  │ │  → 数学/高亮/图表增强 → DOM    │    │
│ └─────┬──────┘ └──────────┬───────────────────┘    │
│       │        状态层(Zustand: 文档/主题/导航)       │
│       └──────── IPC(Tauri invoke / events)─────────┘
└──────────────────────────┬─────────────────────────┘
                           │
┌──────────────────────────┴─────────────────────────┐
│                 Rust 后端(src-tauri)                │
│  fs  │  watcher  │  index(FTS)  │  search  │  export │
│              SQLite(元数据/索引/进度/书签)            │
└────────────────────────────────────────────────────┘
           │
     本地文件系统(用户的 .md / 库目录)
```

### 5.2 渲染管线(前端核心)

```
原始 .md 文本
   │ ① 解析         markdown-it(同步)
   ▼
HTML 字符串
   │ ② 注入增强    代码块→占位符;公式→KaTeX 延迟渲染;图表→容器占位
   ▼
安全化           DOMPurify(sanitize)
   │ ③ 挂载        innerHTML 一次性写入容器(+ index.css 变量)
   ▼
DOM
   │ ④ 视口增强     IntersectionObserver:
   │                 · 进入视口的代码块 → Shiki 高亮(结果缓存 LRU)
   │                 · 进入视口的公式 → KaTeX.render
   │                 · 进入视口的 mermaid → 初始化
   ▼
可交互文档(目录高亮 / 搜索 / 进度)
```

**性能设计要点:**

1. **分段渲染**:长文档按「顶层标题」切块,每块一个 `<section>`,配合 CSS `content-visibility: auto`(Chromium 原生跳过屏外元素渲染),首屏渲染只处理可见块 → 大文件秒开的关键。
2. **高亮/公式/图表全部懒执行**:进入视口才做,结果按内容 hash 缓存(LRU 上限 200 条)。
3. **滚动 60fps**:滚动容器 `overflow-anchor` 处理图片占位;`will-change` 仅用于拆层。
4. **树震动(tree-shaking)**:Shiki 只打包用到的语言(TOP 20 + 按配置),KaTeX 只打包用到的宏。
5. `requestIdleCallback` 分批执行非关键任务(TOC 构建、索引更新),避免阻塞交互。

### 5.3 目录/滚动同步

- 渲染时给每个标题注册 `data-heading-id`,构建 TOC 树
- 用 IntersectionObserver 维护「当前活跃标题」,滚动高亮
- 点击 TOC → `scrollIntoView` 平滑滚动;滚动时防抖(150ms)避免反向高亮闪烁

### 5.4 引擎无关的插件通道

预留 `RendererPlugin` 接口(Tauri 插件或前端函数),第一版仅用于:语法扩展注册、导出格式扩展。第三方插件生态不在本期范围,但接口从第一天就设计好(避免后期返工)。

### 5.5 数据模型(SQLite)

```sql
CREATE TABLE documents (
  id INTEGER PRIMARY KEY,
  path TEXT UNIQUE NOT NULL,        -- 相对库根的路径
  title TEXT,
  mtime INTEGER,                    -- 最后修改时间(用于增量重索引)
  size INTEGER,
  created_at INTEGER,
  last_read_at INTEGER,
  read_progress REAL,               -- 0~1 滚动进度
  last_heading TEXT,
  starred INTEGER DEFAULT 0,
  tags TEXT
);
CREATE TABLE links (
  source_id INTEGER,                -- 文档 id
  target_path TEXT,                 -- [[链接]] 目标(可为未创建文件)
  UNIQUE(source_id, target_path)
);
CREATE TABLE fts (                   -- FTS5 虚拟表,外部内容模式
  doc_id INTEGER UNINDEXED,
  content TEXT
);
```

## 6. UI/UX 设计

### 6.1 布局(三栏,均可折叠)

```
┌──────┬────────────────────────┬───────┐
│ 侧栏  │        正文            │ 大纲  │
│ 文件树│   ┌─ 工具栏 ──────┐    │ TOC   │
│ 搜索  │   │ 路径 | 样式 | 进度│    │ 反链  │
│ 标签  │   └───────────────┘    │ 标签  │
│      │   …正文内容…            │       │
│      │                         │       │
└──────┴────────────────────────┴───────┘
        ▲ 底部状态栏:字数/滚动位置/渲染耗时/缩放
```

- 主体阅读区最大宽度默认 720px,可调(600–1000)
- 所有面板支持拖拽调宽、双击折叠、快捷键切换

### 6.2 主题系统

- 设计 token 层:`--bg / --fg / --text-primary / --code-bg / --link / --accent / --heading-* / --font-serif/sans/mono / --measure`…全部由 CSS 变量承载
- 主题 = token 值的集合;**浅色 / 深色 / 跟随系统**(`prefers-color-scheme`)
- 提供「自定义样式」输入框(实时生效,类似 Typora 的 CSS 主题)
- 代码高亮主题与 UI 主题联动(浅色↔github-light,深色↔github-dark)

### 6.3 排版规范(阅读器灵魂)

- 正文字体栈:中文宋体/黑体回退 + 西文 `Inter`;等宽 `JetBrains Mono`/`Cascadia Code`
- 行高 1.75,段间距 0.75em,标题层级字号递减表(1.8/1.5/1.3/1.2/1.15/1.05)
- 引用块左侧 3px 竖线 + 弱化背景;代码块圆角 + `overflow-x`;表格斑马纹 + 表头吸顶(长表格)
- 图片默认 `max-width:100%` 居中;所有元素间距规则统一收敛在 `prose.css`,与主流 prose 排版规范对齐

### 6.4 快捷键(默认方案)

| 快捷键 | 功能 | 快捷键 | 功能 |
|---|---|---|---|
| `Ctrl+O` | 打开文件/库 | `Ctrl+F` | 文档内查找 |
| `Ctrl+Shift+F` | 全文搜索 | `Ctrl+T` | 新标签页 |
| `g g` | 回到顶部 | `G` | 到底部 |
| `j / k` | 向下/上行滚动 | `[ / ]` | 上一/下一标题 |
| `t` | 打开/收起 TOC | `z z` | 专注模式 |
| `Ctrl+=/-` | 缩放 | `Ctrl+P` | 导出菜单 |

> 细节:快捷键采用「导航态」设计,纯阅读时不与浏览器默认冲突;设置页允许改键(V1 可暂缓)。

## 8. 风险与应对

| 风险 | 等级 | 应对 |
|---|---|---|
| 超大文档(>50MB)卡顿 | 高 | 分段渲染 + `content-visibility`;超阈值文档降级为流式分块加载;M0 就压测 |
| 中文全文搜索质量差(FTS5 分词) | 中 | 预留搜索接口抽象;备用 Tantivy;trigram tokenizer 兜底 |
| Mermaid/KaTeX 渲染卡顿拖慢滚动 | 中 | 一律视口懒加载;图表默认折叠为「点击展开」;提供「禁用图表增强」开关 |
| WebView 三平台差异(特性/字体/打印) | 中 | 前端特性检测统一封装;导出 PDF 用 Rust 侧 webview 打印 API 兜底 |
| markdown-it 生态不满足未来双向编辑 | 低 | 渲染接口抽象,可切 unified 通道,不影响上游 UI |
| 个人项目范围膨胀 | 高 | 严格对照本节 P0/P1/P2;每阶段冻结范围,不做「顺手再加」 |

## 9. 待定决策(需项目方确认)

| # | 决策项 | 选项 | 建议 |
|---|---|---|---|
| 1 | 产品形态 | 桌面(Tauri)/ Web / 两者 | **桌面优先**,Web 作后续轻量版 |
| 2 | 是否含编辑 | 纯阅读 / 轻编辑 / 完整编辑器 | **轻编辑**(V1 内联编辑),完整编辑放 v2 |
| 3 | 渲染引擎 | markdown-it / remark | **markdown-it**(性能优先,理由见 4.2) |
| 4 | 搜索 | SQLite FTS5 / Tantivy | **FTS5 先行**,接口抽象留升级位 |
| 5 | LLM 功能 | 不做 / 本地模型 / 用户自选 API | **不做**(V1),v2 评估 |
| 6 | 插件系统 | 首版开放 / 预留接口 | **预留接口**,暂不开放 |
